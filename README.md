> I build systems where code meets messy reality: trading workflows with<br>
> human approval gates, student tools that replace scattered portals, web<br>
> utilities that earn traffic, and a flapping-wing robot that started as a<br>
> research pitch.

What has stayed constant since school is the pull between hardware and<br>
software — writing the code, then printing the part it has to run on. A CAD<br>
file and a 3D printer turn an idea into something that either works or<br>
visibly doesn't, which is a faster teacher than any tutorial.

The thread through most of my software is narrower than it looks: take<br>
information that is technically public but badly organised, and make it<br>
legible. It began as a scraper for German judicial and insolvency auctions,<br>
written for a course, and grew from there. That is also why markets<br>
interest me — start-ups, investing and M&A are where data analysis stops<br>
being an exercise and starts changing a decision, and where being wrong is<br>
expensive enough to keep you honest.

Away from the keyboard: alto saxophone in the active orchestra of the<br>
Musikverein Kuppingen since 2015, twelve years with the DLRG as a lifeguard<br>
and group leader, and these days the Fresher's Weekend for incoming computer<br>
science students in Stuttgart.

<samp><b>the portrait</b> — the same portrait_ascii.txt the portfolio site prints in<br>
its hero, resampled from 250 columns to 90. The site can afford 250 because it<br>
sizes the block in cqw against a full viewport; a README is ~880px wide, where<br>
250 columns collapse into grey noise. It types itself once with SMIL, then<br>
freezes — GitHub strips scripts, but it does run SMIL.<br>
<br>
<b>the typeface</b> — Fira Code (SIL OFL), subset per role and inlined as base64.<br>
An SVG loaded through &lt;img&gt; cannot fetch a subresource, so an external font<br>
URL silently falls back to the system monospace. Four subsets cost ~15 KB;<br>
inlining the full face into every file would cost megabytes.<br>
<br>
<b>the panels</b> — pitch black by choice, not adaptation. Inside an &lt;img&gt;-loaded<br>
SVG, prefers-color-scheme resolves against the OS rather than GitHub's own<br>
theme toggle, so an adaptive panel would show white ink on a white page for<br>
anyone running OS-dark with GitHub-light.<br>
<br>
<b>the numbers</b> — refreshed daily by a scheduled action, from the GraphQL API,<br>
standard library only. The window is pinned to whole UTC days so unchanged data<br>
renders byte-identically, and the job commits only when something moved.</samp>
